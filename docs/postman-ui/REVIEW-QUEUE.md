# 审核工作队列

本页为 Operate 工作台，优先级为：队列规模 → 状态 → 筛选 → 任务、轮次与下一步。沿用 Forge 导航、系统字体、共享中性色和原有审核工作台。顶部删除开发版标签与跳转入口。

## 页面与组件

- 标题、返回入口及刷新操作；轻量摘要使用数字、文本与竖线，不使用 KPI 卡片。
- 一级状态为待审核与已审核；“全部／我的”已移至审核范围选择器，替代上一版分段控件规范。
- 搜索、范围、审核类型、轮次和排序同区联动；变更条件回到第 1 页。筛选条件可恢复于 URL；重置仅在有条件时出现。
- 六列表格栅格，列顺序固定。标题最多两行；Item ID 为等宽文本；数据集与上次问题进入任务首列。长标题与问题通过原生 Tooltip 提供全文。
- 表头 sticky。桌面行高约 71px、缩略图 72×48px；1440×1000 首屏展示 8 条完整任务，分页固定在队列底部。390px 窄窗筛选换行，表格内部横向滚动，操作列固定在右侧。
- 普通控件沿用中性颜色；首次审核灰色、返工复审低饱和橙、审核中低饱和绿。绿色仅表示领取进行中或结果已通过，各自有明确文案。
- 首次和返工复审统一使用黑色「开始审核」；审核中的条目显示灰色禁用态「审核中」（包括本人、他人领取或已有审核草稿）；查看进度／结果中性描边。按钮固定宽度，不根据文案跳动。
- 未领取、已指派与已领取是不同概念。点击开始审核在本地记录领取，并进入既有审核工作台；已领取任务的 CTA 和任务标题入口均禁用；只有尚不可审核的生产任务保留「查看进度」。
- 已审核复用表格，仅保留查看结果入口；历史记录缺失精确时间时显示“历史记录”，不参与今日统计。

## 数据边界

使用当前 runsData、dsData、assignmentOf、roundsOf、reviewDecisions、既有完成记录与历次反馈，不增加后端。初始当前数据为 19 条待处理、16 条返工后待审；今日数量按当前浏览器日历日和记录时间计算，验证时为 2。

现有分配数据没有独立领取字段。局部样例将天坛的既有审核人 Allen、布达拉宫的既有审核人一万标为正在处理；其余指派仍为未领取。新领取保存在当前页面内存，刷新浏览器后恢复样例，与现有原型内存业务一致。

缩略图只读取精确 Item + Run 的 itemPreviews 或 artifacts manifest；批量运行的通用图片不会被当作每个 Item 的真实产物。图片失败会回退为内容类型图标。当前初始数据未携带真实产物缩略图，因此不拿参考图、UI 截图或 Astronaut 演示模型代替。

没有增加超时、SLA、截止时间、等待时长判断或告警。提交时间仅用于普通展示和排序。

## 实现入口

- `scripts/postman-ui/review-queue.mjs`：定向替换队列区域，保留原有弹窗及审核动作。
- `scripts/postman-ui/review-queue-methods.js`：摘要、筛选、分页、领取及进度入口的局部视图模型。
- `scripts/postman-ui/review-queue.html` / `public/postman-ui/review-queue.css`：页面结构与响应式样式。
- `scripts/postman-ui/routes.js`：type、round、completed、page、size 的 URL 往返。
- `public/postman-ui/behavior.mjs`：状态 Tabs 的方向键操作。

## 验证

自动测试：审核队列 10 项、Postman 生成与业务保留 14 项、路由 12 项、原有审核工作台 13 项，共 49 项。覆盖计数、组合筛选、排序、分页、状态操作、领取冲突、刷新失败、完成记录、URL 恢复、精确缩略图映射与错误回退。

浏览器验证：1440×1000、390×844；组合筛选得到单条布达拉宫；继续审核进入原工作台；今日摘要切换审核结果；上下页、每页数、空结果与重置；窄窗固定操作列与页面宽度。
