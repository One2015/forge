# 运行记录

本轮只替换独立预览中的运行列表视图模型和模板，保持 Forge 顶栏、侧栏、生产导航与新建运行入口。详情中的失败项增加定位钩子，不改审核、Reroll 或运行生成业务。

## 视觉与交互

- 运行摘要复用概览的五栏布局，按运行中、待审核、运行失败、今日成本、模型状态排列；使用上下边线和栏间分隔线，统一标题、黑色数字、辅助说明和信息图标。保留各指标原有统计口径，选中筛选以底部橙色细线标识。悬停背景由内容容器承载，透明点击层不遮挡数字。
- 两级导航参考 GitHub 的层次：生产栏目使用橙色下划线；运行状态使用无描边、浅灰选中背景的紧凑切换。搜索与「只看我的」独立成行，小屏搜索占整行、状态组局部横向滚动。
- KPI 是可取消的筛选按钮，与运行状态、只看我的、搜索联动。搜索支持运行名称、Pipeline、数据集和 Run ID。条件保存在 URL，重置清除条件。
- 连续七列表格：运行、运行状态、Item 状态、发起人／时间、耗时、成本、操作。每行 70px，Sticky 表头；数据集、Run ID、复制按钮在运行列第三行，不设置数据集分组。
- partial 只表示运行完成后仍有失败 Item，列表映射为“运行完成”。运行失败只统计 status=failed。
- Item 进度分别使用浅灰排队、蓝色处理中、暖灰待审核、绿色已通过、红色失败；未完成或取消仍为中性灰。
- 点击整行进入详情，不重复显示查看详情按钮。查看失败项为橙边；查看原因为红边；去审核为浅绿填充。有额外动作才显示灰色更多菜单。运行中使用浅蓝底和时钟标记，运行完成使用浅绿底和对勾。工具栏删除 9 / 9，数量保留在分页区。
- 点击行或键盘 Enter／Space 进入详情。复制、主操作、菜单均隔离冒泡。复制失败显示提示，不伪报成功。
- 小屏保留连续宽表并局部横向滚动；摘要跟随概览响应式换行，状态筛选可横向滚动。不固定覆盖任务文本的操作列。

## 数据契约

`ForgeRunRecords.calculate(records, options)` 是独立纯计算函数，源码在 `scripts/postman-ui/run-records-data.js`。不访问 DOM 或后端，可单独注入测试时钟、调用统计、审核结论和 Item 技术状态。

- 运行计数读取运行 status；待审核按每条运行的 Item 计数汇总。现有 9 条记录为运行中 2、待审核 45、运行失败 2。此口径与审核队列的去重 Item 数不同。
- 今日成本是今日发起运行的费用总和，并按昨日发起运行费用计算变化。优先读取 startedAt／createdAt。旧原型只有相对小时 h，按页面打开时的稳定时间锚计算演示日期，不将 Run ID 当作实际时间来源。验证时为 $2,416.50，较昨日 +104.1%，不是固定金额；跨日期会随记录变化。
- 成本沿用现有模拟运行数据，未接入真实账单。没有接口时不硬填用户举例的 $1,656.28／+18.4%。
- 模型成功率 = successes / calls，按调用数加权，保留一位小数。接入口为 `props.runTelemetry: Array<{runId,calls,successes}>`。未提供接口时使用独立、显式的 `mockTelemetry` fixture，当前为 97.6%；Tooltip 标为示例调用统计。不编造“8 / 8 线路可用”。点击该 KPI 筛选有模型调用统计的运行；当前 9 次运行都有示例统计。
- 耗时优先 durationMs，其次真实 startedAt 与完成时间的差、运行中真实 startedAt 至当前时间、elapsedMs。旧 9 条样例使用独立 mockTimings 快照，Tooltip 标明 Mock 来源；也可通过 props.runTimings 接入。未匹配的缺失数据仍显示 —，排队且未执行为 0 s，不把 createdAt 或提交距今时长伪装成执行耗时。
- 失败项入口进入既有详情，并滚动定位失败 Item；Reroll 仍通过现有逐条流程执行，不引入隐式批量重跑。
