# Task Errors · 2026-09-12

参考：https://copulaai.com/#/task-errors 。已在授权后的真实页面检查 Item / Attempt、创建人和提交时间筛选、趋势、原因分布及执行上下文。

## Review 与落地

- 保留 Item 最终失败与 Attempt 历史失败的区分；取消与正常业务停止排除在错误记录外。失败率分母只包含已结束且未取消的任务。
- 生产二级导航新增「错误分析」，支持独立路由 `/production/task-errors`。
- 四项统计按主次呈现，原因分布可筛选明细，日期趋势保留无错误日期；列表先呈现摘要，执行上下文展开完整日志。
- 创建人、任务提交日期（UTC+8）、统计模式、原因、错误日期、搜索、排序及页码均支持 URL 恢复。明细每页 10 条。
- Run / Item 入口沿用 Forge 路由。演示任务复用有限 Item 快照，因此保留 itemIndex，确保打开正确的本轮执行状态。

## 数据边界

目前 Forge 为原型。新增页面明确标注演示数据，原因和 Attempt 为本地隔离样例，不含认证来源的生产日志。基础任务与最终失败数量来自现有 runsData；不修改业务数据。调用方未来可提供 `props.taskErrorAttempts` 数组，空数组不回退为演示数据。字段为 id、runId、itemId、可选 index、node、status、type、summary、message、at（Unix 毫秒）、可选 businessStop。type 为 validation / sandbox / model / other。身份与权限仍采用现有原型角色体系，实际后台鉴权及生产日志接口不在本次接入内。
